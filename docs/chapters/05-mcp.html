5  Connect to a database (MCP)

Ask an agent for “recent papers on TCF-1 and chromatin in T cells” and it will answer from memory. That memory is large, and it is often right, but it is frozen at the date the model was trained, and it has no way to tell a paper it read from a paper that merely sounds plausible. Language models are known to invent references: in one study, 18% of the citations GPT-4 produced for short literature reviews did not exist, and a quarter of the real ones had substantive errors (Walters and Wilder 2023). Newer models are better at saying “I don’t know”, but “better” is not a standard you can cite.

Walters, William H., and Esther Isabelle Wilder. 2023. “Fabrication and Errors in the Bibliographic Citations Generated by ChatGPT.” Scientific Reports 13 (1). https://doi.org/10.1038/s41598-023-41032-5.
“What Is the Model Context Protocol (MCP)?” n.d. Accessed September 23, 2026. https://modelcontextprotocol.io/docs/2026-07-28/getting-started/intro.

The fix is not a cleverer prompt. It is to let the agent ask the system of record: search PubMed itself, get back real PMIDs, and show you where each fact came from. The Model Context Protocol (MCP) is how that connection is made (“What Is the Model Context Protocol (MCP)?” n.d./). An MCP server sits in front of a database or service and offers the agent a handful of tools, such as “search articles” or “get article metadata”. The agent decides when to call them and what to ask. You add the server once, and from then on it is part of what the agent can do.

In Chapter 4 you gave the agent instructions: how your lab triages a results table. A skill tells the agent how. An MCP server tells it what is there now. This chapter connects one server, PubMed, which needs no account, and then does the thing that matters most: checks what came back.

5.1 What you’ll learn

  • What an MCP server is, and how it differs from a skill.
  • How to connect the PubMed server, three ways: by asking the agent, from the command line, or as a plugin from Anthropic’s life-sciences marketplace.
  • How to compare an answer from memory with an answer from a live database.
  • How to check retrieved results by hand, and why retrieval is not the same as truth.
  • What an MCP server can see, and which servers to trust.

5.2 How an MCP connection works

An MCP server is a small program, usually run by whoever owns the data, that speaks one agreed protocol. When your agent starts, it asks each configured server “what tools do you have?” and gets back a list with names, descriptions and inputs. From then on, whenever a question needs one of those tools, the agent calls it, reads the result and carries on (Figure 5.1).

Protocol: an agreed way for two programs to talk. Because MCP is shared, the same PubMed server works with Claude Code, Claude’s desktop app, Google Antigravity, Codex and Copilot. Only the place you configure it differs.

Two things follow from this picture. First, the agent writes the query. You asked in plain English; the agent turned that into search terms, and a search can match the wrong organism, the wrong assay or the wrong TCF (there are several). Second, the server sees your question, or at least the parts of it the agent sends. Both come back later in this chapter.

5.2.1 Anthropic’s life-sciences servers

Anthropic keeps a list of MCP servers and skills for life sciences in a public GitHub repository, packaged as Claude Code plugins in a marketplace (Anthropic 2026). A plugin is a bundle; a marketplace is a list of plugins you can install by name. The servers themselves are run by the data providers, not by Anthropic. PubMed, which this chapter uses, is one of them; “Going further” lists some of the others (Table 5.5).

PubMed is not in the official Anthropic marketplace that Claude Code sets up for you. To install it as a plugin you add the life-sciences marketplace first. The simpler route, which works in every tool, is to give the agent the server’s address directly.

5.3 Worked example

We asked the same question twice, in two empty folders, with web search and the shell turned off so the only route to PubMed was MCP. First, with no server connected:

Find three papers on how TCF-1 (Tcf7) shapes 3D genome organisation or chromatin in
T cells. For each give the first author, year, journal, title and PMID. Say where each
fact came from.

The bare agent was careful. It said it had no way to look anything up, gave three papers from memory, and left the PMIDs blank, “because I don’t remember them reliably, and a made-up PMID is worse than a blank”. All three papers turned out to be real. But you could not have known that from the answer, and without PMIDs you had to do the searching yourself.

Then we connected PubMed in the second folder, using the .mcp.json file you’ll write in a moment, and asked again. This time the agent searched PubMed twice (search_articles) and fetched the records it found (get_article_metadata), and came back in about 30 seconds with Table 5.2.

Just as useful was what it said about its own work:

  • It picked papers 1 and 3 from their titles alone, and said so: “I didn’t read its abstract.”
  • Paper 2 did not come up in its broad search. It remembered the paper, searched for it by name, and took every detail from the PubMed record. It said that too.
  • Paper 3 is about chromatin accessibility, not 3D structure, which it flagged as a partial fit.

Then we checked. We looked up all three PMIDs directly in PubMed, independently of the agent: every title, first author, journal and year matched. We also checked the paper the bare agent had remembered but the connected one did not use (Shan 2021, Nat Commun); it is real too (Shan et al. 2021).

Shan, Qiang, Xiang Li, Xia Chen, et al. 2021. “Tcf1 and Lef1 Provide Constant Supervision to mature CD8.” Nature Communications 12 (1): 5863. https://doi.org/10.1038/s41467-021-26159-1.

So memory did not fail here, and that is the honest result. What changed is that the answer became checkable: every claim came with an identifier and a stated source, and the agent separated what it had read from what it had inferred from a title.

NoteIs the second paper really about 3D genome structure?

The agent read that abstract and quoted it: Tcf1 and CTCF together “promote chromatin interactions and form highly connected, dynamic interaction hubs”. That is a claim about the paper, not a PMID, and checking it means reading the abstract yourself. That is the part of the check that no tool does for you.

5.4 Your turn

You’ll need about 20 minutes. Inside your agents-workshop folder in Documents (from Setup), make a new folder called mcp, and start a new session on it. Ask “what folder are you in?” to be sure. Everything in this chapter happens in agents-workshop/mcp, and its LEDGER.md lives there too (Chapter 2).

ImportantPrivacy: what leaves your machine

Every tool call sends the agent’s query to the server’s operator. For PubMed that means your search terms: a topic, gene names, a disease. That is usually fine. Don’t put anything in a query you wouldn’t type into the PubMed website: no patient details, and nothing about unpublished work you’ve been asked to keep quiet.

5.4.1 1. Ask first, without a connection

Pick a topic you know well enough to judge an answer: your own field, a method you use, a gene you study. Start a new session and ask:

Find three recent papers on <your topic>. For each give the first author, year,
journal, title and PMID. Say where each fact came from. Don't search the web, and
don't use any PubMed or other database tools.

The last sentence matters: Claude Code can search the web, and your account may already have a PubMed connection (see “Two PubMed servers?” below). Today you want to see what the agent knows without a database. Ask the agent to start LEDGER.md in this folder with an entry for this question: the prompt under Asked, its answer under Agent did.

No topic in mind? Use ours: the question in the worked example. Or use genes from the Vahedi lab’s RNA-seq data: the top hits in differential_genes.tsv, from their repository’s track-a/data/README.md, are Jun, Myc, Irf4 and Ccr7, in B cells lacking a CTCF binding site (Vahedi lab repository).

5.4.2 2. Connect PubMed

Choose one route (Table 5.3). If you’re not sure, use route A: the agent does the work, and it works in the desktop app and the command line alike.

Route A: ask the agent. In a session in your workshop folder, paste:

Create a file called .mcp.json in this folder, containing exactly:

{
  "mcpServers": {
    "pubmed": {
      "type": "http",
      "url": "https://pubmed.mcp.claude.com/mcp"
    }
  }
}

Then create .claude/settings.local.json in this folder (make the .claude folder if
needed; if the file exists, add the key and keep what's there), containing:

{
  "enabledMcpjsonServers": ["pubmed"]
}

Then tell me the full path of both files.

The first file is the project-level MCP file Claude Code reads, in the documented format (“Connect Claude Code to Tools via MCP,” n.d.). The desktop app’s Code tab reads the same file. The second approves the server: Claude Code won’t use a server from .mcp.json until you do, and enabledMcpjsonServers in .claude/settings.local.json is exactly what its approval dialog writes when you say yes (“All Settings,” n.d.). You’re approving it by hand, having read what’s in it, so it works whether you use the desktop app or the command line. Then start a new session in the same folder: servers are loaded when a session starts. If an approval prompt appears anyway, approve it.

“All Settings.” n.d. Accessed September 23, 2026. https://code.claude.com/docs/en/settings-reference.

Route B: the command line. Only if you installed the claude command; the desktop app on its own doesn’t give you one. In a terminal, in agents-workshop/mcp:

claude mcp add --transport http pubmed --scope project https://pubmed.mcp.claude.com/mcp

It writes the same .mcp.json as route A. Leave out --scope project and it’s saved in your personal settings instead, for this folder only. Then run claude and approve the server when asked.

Route C: a plugin from the life-sciences marketplace. In Claude Code, type:

/plugin marketplace add anthropics/life-sciences
/plugin install pubmed@life-sciences

The first command adds the marketplace, the second installs PubMed from it. By default this installs it for you, in every folder, not just this one. We tested the same two steps from the shell (claude plugin marketplace add …, then claude plugin install …) and the server connected. In the desktop app, plugins live under the + button, then Plugins, then Add plugin, which browses the marketplaces you’ve already added. We haven’t confirmed that you can add a new marketplace from there, so if you use only the desktop app, route A is the safer choice.

TipUsing Antigravity, Codex or Copilot?

The server is the same; only the configuration file differs. Ask your agent: “Add a remote HTTP MCP server called pubmed, at https://pubmed.mcp.claude.com/mcp, to your own MCP configuration for this folder, and tell me which file you changed.” Then check the file it names. (In Antigravity it’s .agents/mcp_config.json.)

NoteOn Windows
  • Let the agent create .mcp.json (route A). The name starts with a dot and File Explorer hides extensions by default, so a file made in Notepad can end up called .mcp.json.txt and be silently ignored.
  • Route B’s command is for PowerShell, once claude is installed.
  • Plugins aren’t available in WSL sessions. See Appendix A.
ImportantIf the connection is blocked

Organisations can restrict which marketplaces and servers their members may add. If a route fails with a message about policy or permissions, that isn’t you doing something wrong. Try route A, and if that’s blocked too, ask whoever runs your Claude account.

5.4.3 3. Check what the agent can now do

In the new session, ask:

Which MCP servers are connected, and what tools does each one give you?

You should see a PubMed server with seven tools: search_articles, get_article_metadata, find_related_articles, lookup_article_by_citation, convert_article_ids, get_full_text_article and get_copyright_status. In the command line, /mcp lists each server with its status and number of tools. If PubMed isn’t listed, see “If it goes wrong” below.

NoteTwo PubMed servers?

Servers added to your claude.ai account as connectors also appear in Claude Code when you’re signed in with that account. On Team and Enterprise plans only admins can add them, and an admin can switch on a PubMed connector for everyone. If yours has, your agent had PubMed before you added anything, which is why step 1 tells it not to use database tools. So you may see a “claude.ai PubMed” as well as the one you just added. They reach the same database; either will do.

5.4.4 4. Ask again, with the database

Ask exactly the question from step 1, but take out the last sentence (“Don’t search the web …”) and add:

Use PubMed. For each paper, say whether you read the abstract or chose it from the
title alone.

Put the two answers side by side. What’s different: the papers, the PMIDs, how sure the agent sounds, what it says about where each fact came from?

5.4.5 5. Check three PMIDs by hand

This is the step that counts. For three of the papers, open https://pubmed.ncbi.nlm.nih.gov/<PMID>/ in your browser, putting the PMID in place of <PMID>, and check:

  1. Does the PMID exist, and is it the paper the agent named: title, first author, year?
  2. Is it about what you asked? Right organism, right assay, right gene? A search for “TCF” can find the wrong TCF.
  3. Does the abstract support what the agent said about it? Read it. This is the check no tool can do for you.

Then have the agent add a second ledger entry, and correct it (Chapter 2). Asked is the step 4 prompt; Agent did is how you connected PubMed and what the agent answered; Checked how is the three PMIDs and what you found, in your words; Confidently wrong is anything that didn’t hold up; Keep is what you’d do the same way next time.

5.5 What to notice

  • The agent chose the tools and wrote the queries. You never saw PubMed’s search syntax. That’s convenient, and it’s also where silent errors come from: look at the search terms it used (ask it) before trusting that “no papers found” means none exist.
  • Retrieval is not truth. A real PMID proves the paper exists. It doesn’t prove the paper says what the agent claims, or that it’s the best paper on the topic. The agent in our worked example chose two papers from their titles and said so. Ask yours to do the same.
  • The good answer showed its sources. Compare how each answer said where its facts came from. That, more than the facts, is what the connection bought.
  • You added a capability without writing code. Four lines of JSON, and the agent can now search a database it couldn’t reach before.

TipYou’re done when
WarningWhich servers to trust

A server you connect can see every query the agent sends it, and its answers go straight into the agent’s work. Content a server returns can even contain instructions aimed at the agent (a prompt injection), which is why Claude Code’s documentation says to verify you trust each server before connecting it (“Connect Claude Code to Tools via MCP,” n.d.). Plugins are trusted more still: they can run code on your machine.

  • Install servers from the data’s owner or from a source you trust, such as the NLM, the Open Targets consortium or Anthropic’s own list, not from a random repository.
  • For servers that need an account, treat the token like a password. Don’t paste it into the chat, and don’t put it in a .mcp.json you’ll share or commit.
  • Your institution’s rules on data still apply. A connection doesn’t change what you’re allowed to send.

5.7 Going further

  • A second database. Add Open Targets to the same .mcp.json, as a second entry under "mcpServers" with "url": "https://mcp.platform.opentargets.org/mcp", and ask: “Using Open Targets, what are the top five diseases associated with the human gene IRF4, with their overall association scores?” When we tried it, the answer matched Open Targets’ own API exactly. Then check one of the diseases on platform.opentargets.org: which kinds of evidence hold its score up?
  • Two databases, one question. With both connected, ask a question that needs both: “For the top five IRF4-associated diseases in Open Targets, find one recent review for each in PubMed.”
  • A skill that uses a server. Combine this chapter with Chapter 4: a skill that says “when asked for literature, use PubMed, give PMIDs, and say which abstracts you read”.
  • Build your own server. The Vahedi lab’s afternoon has a pod on exactly this: wiring up a server, or having the agent write a small one around a public API such as Ensembl or GEO: Pod 2, Connect to the outside world.
  • Undo it. Ask the agent to delete .mcp.json and .claude/settings.local.json, or run claude mcp remove pubmed -s project. A plugin can be uninstalled from /plugin, or from Manage plugins in the desktop app.
  • Other life-sciences servers. Anthropic’s marketplace (Anthropic 2026) lists more. Table 5.5 says only what we checked on 23 September 2026.
